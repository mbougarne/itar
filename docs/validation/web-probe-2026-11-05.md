## Behavior and validation boundaries

- Web renders the existing OTT screens through React Native Web. Bundles include
  the C++ engine's Wasm bytes, so local TV packaging does not need to fetch a Wasm
  resource. The generated loader contains no Node imports.
- Scope gates, entry history and directional destinations belong to C++. The DOM
  host measures real elements, issues focus, observes the actual result and then
  acknowledges it. Input focus never fabricates accessibility focus.
- Rows and items use bounded windows plus retained source/destination indices.
  Delayed realization, cancellation, remount identity and original deadlines are
  checked against the compiled engine in Node with synthetic DOM effect objects.
  These tests do not exercise a browser layout engine.
- Tab, pointer activation, text inputs and HTML video retain browser behavior.
  A labelled checkbox disables TV arrow interception and cancels pending work;
  no automatic screen-reader detection is claimed.
- Web uses offline catalogue fixtures. The native TMDB proxy's Origin/Host checks
  and server-only credentials are unchanged. Native live-data startup is separate.
- Home's Hero is a real leading collection row. Its differing height participates
  in native reveal planning. Observed content focus requests an offset of at least
  the Hero height; Hero focus returns to zero. Deeper offsets remain intact.
- Browser output is served over HTTP. Tizen output is unsigned package staging;
  webOS output is CLI package staging. Signing, installation, reader behavior,
  remote/media integration and runtime compatibility are still unverified.

## Reproduction

Use Node 22.23.4/npm 10.9.9 and the local Emscripten 6.0.13 setup in
[engine instructions](../probe-web-engine.md). Build/test commands start no app:

```sh
npm run build
npm run typecheck
npm run typecheck:web
npm run lint
npm run check:tv
npm test
npm run build:web:engine
npm run test:web
node apps/probe/web/build.cjs browser
node apps/probe/web/build.cjs tizen
node apps/probe/web/build.cjs webos
```

The web CI job performs engine/type/host checks and all three target builds,
without launching apps. Workflow syntax is checked with actionlint 1.7.11.
Swift production boundary tests and a Kotlin JVM offset harness check native
leading-row metadata; full Android instrumentation is added but was not run.

[Run and package instructions](../probe-web.md) explain the produced directories
and how the owner can start the browser or package for a TV. No server, browser,
application, device, emulator or simulator was started during this task. Full
browser and physical-TV focus/accessibility/playback acceptance remains pending.

## Browser refresh persistence — 2026-11-05

Root cause: authenticated, profile and mode were initialized from fixed defaults
on every page load, resetting web to fixtures and the welcome screen. Added
`itar.probe.session.v1` localStorage with only signedIn, mode and selected profile.
A valid stored session restores Home. Sign-out synchronously removes the record.
Native platforms do not use browser storage; malformed/blocked storage returns
to a usable demo flow. Emails, passwords and API keys are never persisted.

Four session regression tests pass: fresh-instance restoration, logout cleanup
without clearing unrelated keys, malformed data and blocked/native storage. Web
and native TypeScript, targeted ESLint and all three web bundles pass. In Chrome
selected Stargazer and TMDB, then refreshed. Later observed Stargazer and real
TMDB content while the user was navigating; automation timeouts prevented a
controlled full refresh/sign-out/refresh verification. Do not treat that full
UI sequence as passed. Live backend connectivity still depends on its process.
