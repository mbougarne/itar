## Ruby dependency conflict — unresolved

`bundler-audit 0.9.3 check --update` reproduces
[GHSA-8474-xrp6-wh69](https://github.com/rails/rails/security/advisories/GHSA-8474-xrp6-wh69)
with advisory database `516ea4757d5eec778c49af8371c23309c4b70f42`.
Local audit used Ruby 3.4.2; CI uses Ruby 3.3.6.
Patched ActiveSupport ranges are `~> 8.0.5, >= 8.0.5.2` or `>= 8.1.4.1`.
CocoaPods Core 1.16.2 requires `>= 5.0, < 8`, including in the inspected
[upstream gemspec](https://github.com/CocoaPods/Core/blob/master/cocoapods-core.gemspec).
A direct dependency bump therefore cannot resolve this combination.

The advisory concerns unsafe regex work in `safe_constantize`, including
untrusted ActionCable channel names. Ruby is used for CocoaPods/Xcode build
tooling here, not a deployed Rails/ActionCable service. Searching installed
CocoaPods/Core, xcodeproj and repository scripts found no direct calls to
`safe_constantize` or `constantize`; this is not proof of complete unreachability.

Owner decision: keep the audit blocking and finish the Android fix only.
No advisory exception, audit suppression, or Ruby dependency change is applied.
Repository checks and Required checks remain blocked by this vulnerability.
Dependency remediation remains separate follow-up work.
