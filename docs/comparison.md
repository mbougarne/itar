# Choosing a focus library for a TV app

[العربية](ar/comparison.md) · [Documentation](README.md)

Upstream documentation checked on 18 November 2026.

If you ship a React app in a TV browser, Norigin offers the clearest starting point of these three. If you want one navigation tree for React Native and web, look at BAM’s React TV Space Navigation. If a native TV app needs to keep track of a card while its view is recycled and know whether focus actually reached it, that is a good reason to evaluate Itar. [Norigin’s platform matrix](https://github.com/NoriginMedia/Norigin-Spatial-Navigation#supported-devices) · [BAM’s design](https://github.com/bamlab/react-tv-space-navigation#why) · [Itar’s architecture](guides/architecture.md)

## Where each project helps

| A decision your team faces | What the projects offer |
| --- | --- |
| Ship a React catalogue on Samsung Tizen and LG webOS | **Norigin** publishes React hooks that attach to existing elements. Its maintainers report production use on both platforms. A browser overlay shows candidate bounds and where an arrow press will go, useful when cards have different widths. Itar’s web adapter lives in the Cinema example. Its Tizen and webOS builds produce unsigned staging directories, with physical testing still open. [Norigin installation](https://devportal.noriginmedia.com/docs/Norigin-Spatial-Navigation/guides/installation/) · [Norigin’s selection and visual debugging](https://devportal.noriginmedia.com/docs/Norigin-Spatial-Navigation/guides/distance-calculation/) · [Itar’s web TV guide](devices/web-tv.md) |
| Share a sidebar, rows and grids across native TV and web | **BAM** lets you describe a horizontal or vertical tree and uses LRUD to traverse it. Its components include virtualized lists and grids. This is a convenient way to make the same logical movement rules apply across platforms. The maintainers flag a limitation when virtualizing hundreds of rows. **Norigin** also provides React Native TV bindings that measure native views and handle the remote. [BAM’s components](https://github.com/bamlab/react-tv-space-navigation/blob/main/docs/api.md) · [BAM’s known limitations](https://github.com/bamlab/react-tv-space-navigation/blob/main/README.md) · [Norigin’s native adapter](https://devportal.noriginmedia.com/docs/Norigin-Spatial-Navigation/guides/react-native-tv/) |
| Distinguish a requested destination from a completed native move | **Itar** gives each command a cancellable request. An `applied` result requires the host to confirm input focus on the matching target. It tracks the logical occurrence, its registration and the current view separately so that a callback for a recycled view cannot complete a newer request. Norigin also supports stable focus keys. Its documented `setFocus(key)` API returns `Promise<void>`. [Itar’s command contract](guides/integration.md) · [Itar’s request and outcome types](../packages/itar/src/api/types.ts) · [Norigin’s focus API](https://devportal.noriginmedia.com/docs/Norigin-Spatial-Navigation/guides/programmatic-focus/) |
| Keep native focus feedback working while JS is busy | **Itar** runs supported moves between mounted targets and the host’s focus styling on the native side. Rendering a new React cell can still need JavaScript. UIKit retains control of ordinary mounted directional focus on tvOS. The beta’s lists require fixed extents, support two levels and accept up to 256 logical nodes including scope nodes. [Itar’s native focus path](guides/architecture.md) · [Collection limits](guides/collections.md) |

## Try the same return journey

Put the same film in *Featured* and *Watch again*. Open its second appearance, reorder that rail while Details is open, then press Back. Record which card is focused, whether it is visible and what Select opens.

- **Norigin.** Give each appearance its own `focusKey`, save the opener’s key and use the documented registration check before calling `setFocus`. Decide what your UI should do when the requested component has yet to mount. [Programmatic focus](https://devportal.noriginmedia.com/docs/Norigin-Spatial-Navigation/guides/programmatic-focus/)
- **BAM.** Keep an entry ID and resolve its new index after the reorder. A virtualized list exposes `focus(index)` for an explicit return. Include the list length and number of rows you expect to ship when evaluating the result. [Virtualized list API](https://github.com/bamlab/react-tv-space-navigation/blob/main/docs/api.md#spatialnavigationvirtualizedlist)
- **Itar.** Save the activated occurrence and wait for the returning collection to become ready. Android supports `restoreFocusByKey` and reports a terminal outcome. With a screen reader in control, this restoration is limited to a mounted, visible, eligible target. Apple and the browser example return `unavailable` for this particular command. [Route restoration](guides/integration.md) · [Device status](devices/README.md)

For accessibility, repeat the journey with the platform reader enabled. Check what it speaks, which element it visits and what activates. BAM describes its TalkBack integration as experimental. Itar observes input focus separately from accessibility focus, and its physical reader checks remain open. [BAM accessibility notes](https://github.com/bamlab/react-tv-space-navigation/blob/main/docs/accessibility.md) · [Itar device checks](devices/README.md)

Both alternatives have installable packages. Itar’s native package is a source beta that you can pack locally. The example includes an eight-target native comparison screen with BAM 5.2.0 and a controlled JS workload. It covers mounted navigation only. Comparable measurements on the same TV are still needed to rank latency, memory use or responsiveness.
