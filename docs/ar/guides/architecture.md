# كيف يعمل محرّك التأشير؟

[فهرس الأدلة العربية](../README.md) · [English](../../guides/architecture.md)


تخيّل مشاهدًا يضغط السهم الأيمن عند آخر بطاقة ظاهرة في صفّ. العنوان التالي موجود في الكتالوج، لكن القائمة قد تكون أعادت استخدام عنصر عرضه الأصلي. يحتفظ إطار بالوجهة المنطقية بينما ينشئ المضيف عنصر عرض لها ويمرّر إليه ويقيسه. وقد يعكس المشاهد الاتجاه في هذه الأثناء. لذلك يحتاج المحرّك إلى تتبّع الطلب الذي ما زال صالحًا ورصد العنصر الذي تلقّى التأشير بالفعل.

تعمل نواة C++ نفسها مع أنظمة تأشير مختلفة. تختلف إمكانات الرصد وإجراءات الاختبار من مضيف لآخر. [أدلّة الأجهزة](../devices/README.md)

## الهويّة والحالة

يحدّد **مفتاح الظهور** موضعًا في التطبيق، كالبطاقة الأولى في صفّ العروض المميّزة. وقد تظهر المادة ذات معرّف المحتوى نفسه في صفوف أخرى. يتألف **مقبض العقدة** من خانة في السجلّ وجيل تسجيلها. إذا حُذف عنصر ثم سُجّل من جديد فقد يستعيد الخانة نفسها بجيل جديد. ويُميّز **جيل التركيب** بين عناصر العرض الأصلية المتعاقبة للتسجيل نفسه. أمّا **دورة حياة السطح** فتفصل بين مالكَين مختلفَين حتى لو أعاد السطح الجديد استخدام مفاتيح التطبيق نفسها. [أنواع الهويّة](../../../core/include/itar/identity.hpp) · [أنواع المعاملات](../../../core/include/itar/transaction.hpp)

تعتمد `State` التصريحات المرتبطة معًا في مراجعة واحدة. تسمّي دفعة التحديثات السطح والمراجعة المتوقّعة. تتحقّق النواة من صلاحية البنية المقترحة قبل نشرها. ويستطيع المضيف، بصورة مستقلّة عن الدفعة، إبلاغها بفصل عنصر عرض أصلي. إذا رُفضت الدفعة لاحقًا، تظلّ واقعة الفصل سارية. يتضمّن كل قياس هويّة السطح وجيل التركيب وهويّة التخطيط؛ فلا يلبّي قياس من نسخة قديمة طلبًا لنسخة أحدث. [بروتوكول التعديل](../../../core/include/itar/batch.hpp) · [السجلّ](../../../core/include/itar/registry.hpp)

لكل من تأشير **الإدخال** وتأشير **إمكانية الوصول** قناة رصد مستقلة. تعني `managed` أنّ إطار يعرف الهدف الفعلي، و`unmanaged` أنّ التأشير لدى أداة خارجة عن إدارته. تعني `absent` أنّ المضيف تحقّق من غياب أي هدف مؤشَّر إليه، بينما تعني `unknown` أنّه لم يتمكّن من تحديده. يعتمد التنقّل وسجلّ النطاق والتفعيل على هذه الفروق. يمكن لقارئ الشاشة تفعيل عنصر دلالي يختلف عن عنصر تأشير الإدخال. [التأشير وسجلّه](../../../core/include/itar/focus.hpp)

## كيف يختار المحرّك وجهة في اتجاه معيّن؟

يتبع الصفّ ترتيبه المعلَن للحركة الأفقية، والعمود ترتيبَه للحركة العمودية. يتجاوز المحرّك العناصر المعطّلة ويحفظ موقع العناصر التي خرجت من الشاشة. عند الحافة، قد يتوقّف أو ينتقل إلى الطرف الآخر أو يتابع في النطاق الأب، بحسب سياسة النطاق. ويمكن حصر الحركة في النطاق النشط. حين تتعادل الوجهات، يحسم الخيار ترتيبُ العناصر ومفتاحُ الظهور. لذلك لا يكفي تغيّر خانة العنصر بعد إعادة استخدامه لكسر التعادل بطريقة مختلفة. [سياسة الترتيب](../../../core/src/navigation_order.cpp) · [سياسة الحدود](../../../core/src/navigation_boundary.cpp)

للحركة المكانية، يجب أن تتقدّم حافّتا مستطيل الوجهة بالنسبة إلى حافّتَي مستطيل المصدر على محور الحركة. قد يمتدّ صفّ أسفل لوحة مفاتيح البحث إلى يمينها لكنه يبدأ إلى يسارها. تقدّم مركزه وحده لا يجعله وجهة للسهم الأيمن داخل اللوحة. ومن بين المستطيلات المؤهّلة يرتّب المحرّك المرشّحين بحسب الفجوة الأمامية والفصل على المحور العمودي على الحركة وإزاحة المركز. ولا يطلب نقل التأشير إلى عنصر مركّب إلا بعد الحصول على قياس حديث ومرئي. [سياسة القياسات](../../../core/src/navigation_geometry.cpp) · [اختبارات المناطق](../../../core/tests/navigation_regions.cpp)

عندما يتابع المحرّك البحث في النطاق الأب، ينطلق من موضع العنصر الذي يحمل التأشير. ويظلّ موضع الانطلاق نفسه إذا تحرّك عنصر آخر داخل النطاق. فإذا ضمّ عمودٌ عدّة صفوف، حدّد ترتيبها الرأسي. وتنطبق القاعدة نفسها عند تبديل المحورين، فيحدّد الصفّ الترتيب الأفقي للأعمدة التي يضمّها.

إذا ضغطت السهم السفلي من أحد أزرار تصفية الأنواع فوق الشبكة، يختار إطار أول صفّ يمكن دخوله، ثم ينقل التأشير إلى البطاقة الأقرب أفقيًا إلى مركز الزر. وإذا دخلت الشبكة من أسفل بالسهم العلوي، يبدأ من آخر صفّ يمكن دخوله. ويمكن للنطاق المضبوط على استعادة التأشير عند الدخول أن يعيدك إلى آخر بطاقة أُشير إليها. [اختبار دخول النطاق](../../../core/tests/navigation_entry.cpp)

## تتبّع حركة إلى عنصر خارج الشاشة

1. **رصد الإدخال.** يحدّد المضيف المصدر والجهة التي تتولّى الإدخال والسطح النشط. قد يكون الإدخال من اختصاص محرّر نصي أو أداة أصلية أو قارئ الشاشة. عندئذ يتركه الموائم لتلك الجهة.
2. **اختيار الهدف المنطقي.** تقرأ النواة آخر لقطة معتمدة. يمكن للصفوف والأعمدة اتّباع الترتيب المعلَن، بينما تستخدم الحركة المكانية الحدود المقاسة وقاعدة ثابتة لحسم التعادل. تضبط سياسات الحدود والحصر ودخول النطاق مجال البحث. لا يسبّب الاستعلام وحده تمريرًا أو نقلًا للتأشير. [سياسة التنقّل](../../../core/include/itar/navigation.hpp)
3. **بدء المعاملة.** يسجّل المحرّك الطلب وموعده النهائي الأصلي ومجموعة البيانات والمصدر والوجهة. إذا لم يجد عنصر عرض صالحًا، يطلب إظهار الوجهة أولًا. يمكن ضمّ تكرارات متتالية للاتجاه نفسه إلى هذا الطلب. أمّا عكس الاتجاه فيُحسب انطلاقًا من التأشير المرصود.
4. **تجهيز الوجهة وتنفيذ الأمر.** يعيد المضيف التحقّق من صلاحية العملية قبل تنفيذها. في الصفوف المتداخلة يمكن تجهيز الصفّ أولًا ثم البطاقة. عندما تُعتمد الخلية المطابقة وتُقاس حديثًا، يستطيع المحرّك طلب نقل التأشير إليها. قد تَرِد الاستدعاءات الأصلية بالتزامن مع تنفيذ الأمر، فيضع المضيف نُسخًا من الملاحظات في طابور ويعالجها على الخيط الذي يديره. [دورة عرض الخلية](collections.md)
5. **التأكيد أو الإنهاء.** يبقى الطلب معلّقًا إذا اكتفى النظام بقبول استدعاء واجهته. يكتمل حين يرصد المضيف وصول تأشير الإدخال إلى الهدف المطابق. تنتهي صلاحية الطلب عند انتهاء مهلته أو إلغائه أو التخلّص من السطح أو حلول طلب أحدث محلّه. قد تحدّث ملاحظة حقيقية متأخرة حالة التأشير الحالية مع بقاء الطلب القديم منتهيًا. [اختبارات إعادة تشغيل الأحداث](../../../core/tests/transaction_replay.cpp)

يتبع التمييز المرئي التأشير الفعلي لدى المضيف. يجب اعتماد التسمية والدور وحالة التمكين عند تأهّل الهدف. لتشخيص قفزة غير متوقّعة، سجّل مفتاح المصدر وجيل تركيبه ومعرّفَي الطلب والعملية ومجموعة البيانات والملاحظة الأخيرة للمضيف. قارن قناتَي الإدخال وإمكانية الوصول على حدة. ظهور البطاقة يثبت عرضها، ورصد المضيف يكشف ما إذا كانت تلقّت التأشير.

## تجربة النواة دون React

يمكن تشغيل النواة على جهاز التطوير باستخدام CMake 3.20 أو أحدث ومترجم يدعم C++20. تشغّل الأوامر التالية الاختبارات الحتمية، ومنها محاكاة تنقّل مرتّب وتركيبات قديمة وإدخال متكرّر وإلغاء الطلب.

<div dir="ltr">

```sh
cmake -S core -B build/core -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build build/core --parallel 2
ctest --test-dir build/core --output-on-failure
```

</div>

لتجربة تطبيق C++ مصغّر، احفظ الملفّين التاليين في مجلّد جديد. يسجّل المثال عنوانًا منطقيًا ثم يستخرج مقبضه. يبدأ السجلّ دون عنصر عرض مركّب، وهي حالة صحيحة لعنوان معروف يقع خارج الشاشة.

**main.cpp**

<div dir="ltr">

```cpp
#include <itar/state.hpp>
#include <iostream>
#include <span>

int main() {
  itar::State state{itar::SurfaceId{1}};
  itar::Mutation title;
  title.key = itar::OccurrenceKey::compose("home", "featured", "opening");

  const auto result = state.apply({
      state.surface(), state.snapshot().revision, std::span{&title, 1}});
  if (result.status != itar::BatchStatus::valid) {
    return 1;
  }

  const auto& registry = state.snapshot().registry;
  const auto handle = registry.find(title.key);
  const auto* record = registry.lookup(handle);
  if (!record) {
    return 1;
  }
  std::cout << "Registered " << registry.size()
            << " title, mounted = " << std::boolalpha << record->mounted << '\n';
}
```

</div>

**CMakeLists.txt**

<div dir="ltr">

```cmake
cmake_minimum_required(VERSION 3.20)
project(itar_example LANGUAGES C CXX)
add_subdirectory("${ITAR_SOURCE_DIR}/core" itar-core)
add_executable(example main.cpp)
target_link_libraries(example PRIVATE itar::core)
```

</div>

<div dir="ltr">

```sh
cmake -S . -B build -DITAR_SOURCE_DIR=/absolute/path/to/itar -DBUILD_TESTING=OFF
cmake --build build --target example
./build/example
```

</div>
